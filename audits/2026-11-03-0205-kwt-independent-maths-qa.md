## Verified narrow production fix — incorrect local-date Ready indicator

**Observed bug:** `assigned-practice.js` used the browser's local calendar date for its `Ready` button. Live PostgreSQL timezone is **UTC** and `grove_task_start` enforces `due_date <= current_date`. At **2026-11-02 23:03 UTC**, the database still returned **2026-11-02** while Kuwait local date was **2026-11-03**. A Kuwait browser could therefore display `Ready` for a 3 November assignment during 00:00–02:59 Kuwait while the server would reject its start as too early.

**Fix:** `assigned-practice.js` now uses `new Date().toISOString().slice(0,10)` for the availability date. One-line change, [commit 48d063e](https://github.com/Mathora-mathematics/Mathora/commit/48d063e26c22573d0ed6d16148a2a9730f0a6ec0). Verified source read-back and ESM syntax parsing. Added four UTC/Kuwait midnight-boundary regression cases in [`scripts/check-practice-utc-date.mjs`](https://github.com/Mathora-mathematics/Mathora/blob/main/scripts/check-practice-utc-date.mjs), wired into [Pages CI](https://github.com/Mathora-mathematics/Mathora/blob/main/.github/workflows/pages.yml). The change affects only the browser's availability display, not database scheduling, student work or grades. It does not fix mathematical-family mock readiness.
